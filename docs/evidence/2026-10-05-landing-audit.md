# Landing repository audit

Scope: `Daclify/www-landing-page`, baseline `ce1b271`. The user requested discovery, audit, safe implementation and verification. Work is isolated on `codex/landing-audit`; no production hosting, app/backend/contracts or database changes are in scope.

## System and baseline

Node 24.21/npm 11.19 drive a strict TypeScript static generator. Typed English, Spanish and Polish content supplies 15 HTML pages, metadata/JSON-LD, sitemap, robots, llms and Markdown exports. Local assets contain the established frontend identity and fonts. The repository-root export supports existing plain static hosting; `dist/` is the preferred deployment. Preview tooling serves the generated tree on loopback. There is no browser application bundle, backend, database, credential store or payment handling here. App/handbook/community links are external destinations.

Read manifests, compiler/Playwright/CI configuration, all rendering/build/export/preview code, content/types/routes, CSS/assets, existing tests, documentation and tracked legacy files. Two read-only reviews independently covered UI/SEO/accessibility and tooling/dependencies. Seven direct development dependencies have actual callers. Baseline unused-local/parameter checks also passed. The CSS is large because it contains the visual system and responsive states; size alone does not justify splitting it.

Baseline: type checking, formatting, 25 Node checks and exact exports passed. `npm audit --json` reported zero known advisories for the locked 12-package development dependency tree. CI has immutable action pins, read-only permissions, a locked install and no deployment step. Baseline browser checks use an isolated audit-worktree server to avoid the pre-existing main preview.

## Findings and ordered implementation plan

| Priority | Location               | Verified problem and impact                                                                                                                                | Narrow fix / verification                                                                                                                                                                                                 |
| -------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Medium   | `tools/export.ts`      | A later missing source fails after earlier destinations have already changed. An empty manifest exits successfully.                                        | Validate a non-empty, unique manifest and pre-read all source files before writes; fixture regressions must prove existing files remain unchanged.                                                                        |
| Medium   | `tools/export.ts`      | A destination symlink makes a safe-looking export path overwrite a file outside the checkout.                                                              | Reject source/destination symlinks and non-file artifacts, including ancestor links, before writes; use temporary-directory sentinel fixtures. This is local tooling risk, not a remotely exploitable production service. |
| Medium   | `playwright.config.ts` | The browser command does not build and can reuse a different worktree's port 4179 preview, giving misleading results.                                      | Build the tested checkout, use a separate fixed test port and disable server reuse; prove independent startup from missing build output.                                                                                  |
| Medium   | `assets/site.css`      | The decorative orbit overflows the homepage at 1151–1239px. At 1151px the document is 1193px wide.                                                         | Bound the decorative orbit to available layout space; cover breakpoint boundaries in all three languages without hiding page overflow.                                                                                    |
| Medium   | `tools/serve.ts`       | Lexical containment allows a link to serve a fixture outside `dist/`; both file and directory links returned 200.                                          | Resolve physical paths and enforce the output boundary; HTTP fixtures prove outside links return 404 while in-tree links remain readable. Loopback preview only; no production server is provided.                        |
| Low      | `tools/serve.ts`       | Every filesystem error becomes 404, hiding configuration/read failures. A cyclic-link fixture demonstrates the distinction.                                | Return generic 500 plus an operator diagnostic for unexpected errors; preserve 404 for missing paths and test against raw error disclosure.                                                                               |
| Low      | `tools/build.ts`       | Whole-folder copying publishes unrelated authoring files; missing runtime assets do not fail validation, and missing font inputs erase the previous build. | Publish only declared runtime assets and read/render inputs before replacing `dist/`; fixture tests cover each failure and output preservation.                                                                           |
| Low      | Renderer/compiler/CSS  | Main/closing app actions duplicate the same component; obsolete status styling remains after the copy revision. Unused-code compiler guards are absent.    | Consolidate the shared action markup, remove confirmed unused rules and enable compiler guards; preserve the generated behavior and verified visual states.                                                               |

Implementation order: export regressions and fix; independent browser startup plus layout regression/fix; targeted preview/build boundary checks; verified cleanup; broad checks; diff review and evidence update. No new dependencies, framework replacement, API change or persistent-data migration is needed.

## Boundaries and deferred work

The initial audit retained legacy standalone images as a precaution about older public URLs. The user subsequently requested cleanup; all ten unreferenced root images/icons are now removed, as recorded below. They were already outside the preferred `dist/` payload. Static-site source review does not establish live app availability, contracts/custody correctness, actual host headers, indexing, rankings or native-speaker translation quality. Production app and direct handbook routing remain publication checks from the existing SEO guide.

## Implemented and verified

All safe findings above are addressed in version `2.0.0-alpha.4`. No new dependency or application framework was added. Build/export/preview remain separate CLI responsibilities; export fixture tests now have their own file instead of living inside HTML/SEO tests. Main/closing app buttons share one renderer. Removed the unreachable `principle` badge rule and enabled `noUnusedLocals`/`noUnusedParameters`.

Actual verification:

- Baseline: 25 Node and 42 isolated desktop/mobile browser cases passed, plus type, formatting and export checks.
- Eight new export cases failed against the original exporter, then passed after preflight/path fixes.
- The intermediate-width browser regression failed at 1151px before the CSS fix, then passed across all three homepages at 900, 901, 1150, 1151, 1200, 1240 and 1440px.
- Outside-file/directory preview link tests failed with 200 before physical-path confinement, then returned 404. In-tree links remain readable. Actual HTTP fixtures also exercise GET, HEAD, POST rejection, malformed encodings, encoded traversal, MIME types and missing paths.
- Missing build assets and unexpected authoring files failed the original build acceptance checks. Separately reran the missing-font and unexpected-filesystem-error regressions with their original scripts, observed failures, restored fixes and verified passing results.
- Final `npm run typecheck`, `npm test` (42 Node cases), `npm run check:export`, `npm run test:e2e -- --reporter=dot` (44 desktop/mobile cases), `npm run format:check` and `git diff --check` passed. Before the final E2E run, removed only the disposable audit `dist/`; the E2E command rebuilt and served its own checkout on 4180 while the main preview remained on 4179. This verifies that no prebuilt site or unrelated preview is required.
- Final `npm audit --json` reported zero known advisories. This is registry advisory evidence, not a guarantee against undiscovered vulnerabilities.
- Independently compared all 15 generated HTML pages to `ce1b271`: byte-identical. The read-only UI reviewer also compared baseline/current full-page screenshots for all three languages at 1440px and 390px; all six pairs matched. Source diff review found no further concrete regressions.
- Current generated output: 45 files, 714,044 bytes, no client JavaScript files. Homepage: 20,529 bytes (4,708-byte gzip estimate); CSS: 21,532 bytes (4,939-byte gzip estimate). These are file-size measurements, not deployed transfer sizes or Core Web Vitals. There is no evidence that caching, bundler replacement or additional infrastructure would improve this small static site.

No critical/high finding was identified in this scope. No unresolved code failure or mandatory product decision remains. Local preflight is not an atomic multi-file publication mechanism or a sandbox against concurrent malicious filesystem changes; the README states those limits. Safari/Firefox, production headers/caching, real app/handbook availability, search indexing and native-speaker editorial review were not exercised. Those deployment/editorial checks are follow-up work, not reasons to replace the approved product design or add application services here.

## Asset cleanup following user feedback

The user questioned the retained files. Retention was a conservative implementation choice about possible old public URLs, rather than a requirement for the current site. Rechecked exact filenames across source, tools, tests, CI, assets, generated pages and configuration: no current references were found.

Removed `Time2PlanetLogo.png`, `TonomyLogo.svg`, `boid_logo.png`, `daclify-assistant.png`, `daclifyLogo.png`, `favicon.ico`, `fiddlLogo.svg`, `pintastic-logo.png`, `spain-48.png` and `uk-48.png`: 925,342 bytes from the working tree. Git history retains the prior content. Added a Finder metadata ignore rule; preserved the existing untracked local metadata. Current branding/font assets, generated HTML/Markdown/discovery exports, source, tests and tooling remain active.

Version `2.0.0-alpha.5`: 42 Node and 44 desktop/mobile browser tests passed after removal, along with type checking, formatting, exact export checks and diff checks. The cleanup changes no runtime source or product copy. Updated the README/spec and implementation evidence to replace the temporary legacy-retention policy.
